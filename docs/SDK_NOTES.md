# SDK notes — VisioOne in React Native

Integration notes for running the VisioOne SDK in a React Native app through `react-native-webview`, with the SDK loaded as an ES module from the Visioglobe CDN (see [`src/webview/core.js`](../src/webview/core.js)).

## Why the page is loaded inline rather than with `require()`

This project loads the SDK host page with:

```tsx
<WebView source={{ html: visioOneHtml, baseUrl: 'https://cdn.visioglobe.com/' }} />
```

rather than the more obvious:

```tsx
<WebView source={require('../assets/visioOne.html')} />
```

`visioOneHtml` is a string module generated by `scripts/build-webview.mjs` from `src/webview/index.html`, with every script it lists inlined (see the README's Setup section).

### The symptom

Loading the page as an HTML file with `require(...)` in a Debug build connected to Metro, the map did not show: the SDK only reported a generic `"Cannot load the venue"` error.

### Root cause

Logging the SDK's warnings and every `fetch` the page made revealed the hidden error:

```
[console.warn] VisioOne error: Error: Hash not found
```

with this network detail:

```
location.href = http://localhost:8081/.../index.html?platform=ios&hash=b52c3a3b3521fadf7f0e0299fdcc22fb
[fetch] https://mapserver.visioglobe.com/b52c3a3b3521fadf7f0e0299fdcc22fb/descriptor.json -> 404
```

The SDK used `b52c3a3b3521fadf7f0e0299fdcc22fb`, **not** the hash passed in code. That value comes from the `?hash=...` query parameter **Metro** appends to the URL of any local asset loaded with `require()` in Debug — a Metro cache key, unrelated to VisioOne.

The SDK merges the page URL's query parameters into the `loadVenue` options. Between SDK **1.0.3** and **1.0.5** the priority of that merge flipped:

| SDK version | Hash actually used | Result |
|---|---|---|
| **1.0.3** | the one passed in code | `descriptor.json` → 200, map loaded |
| **1.0.5** | the one from the URL (Metro's `?hash=`) | `descriptor.json` → 404, "Hash not found" |
| **1.0.9** | the one passed in code (option renamed `vg_maphash`) | `descriptor.json` → 200, map loaded — Metro's `?hash=` is no longer read |

The trap only exists in a **Debug build connected to Metro**: in Release, assets are bundled in the app and served without a query string.

### The workaround used here

Loading the HTML as a string (`source={{ html, baseUrl }}`) avoids the Metro-served URL entirely. The `baseUrl` is required: without it the document's origin is opaque (`null`), which breaks the SDK's internal logger (based on `localStorage`) with `SecurityError: The operation is insecure`.

| Setup | `location.origin` | Result |
|---|---|---|
| `source={require('./visioOne.html')}` | `http://localhost:8081` (+ Metro's `?hash=`) | ❌ Metro's hash overrides the one in code (SDK 1.0.5) |
| `source={{ html }}` **without** `baseUrl` | `null` (opaque origin) | ❌ no hash collision, but `SecurityError` on `localStorage` |
| `source={{ html, baseUrl: 'https://cdn.visioglobe.com/' }}` | `https://cdn.visioglobe.com` | ✅ works, including in Debug connected to Metro |

The last setup is the one used in [`src/bridge/VisioMapView.tsx`](../src/bridge/VisioMapView.tsx).

### Since SDK 1.0.6: `vg_maphash`

SDK 1.0.6 renamed `LoadOptions.hash` to `LoadOptions.vg_maphash` (a breaking change: a `hash` passed to `loadVenue` is ignored and loading fails with `Hash not found`). The URL parameter the SDK reads was renamed the same way: it now only reads `?vg_maphash=` (and `?baseURL=`), not `?hash=`. Metro's `?hash=` therefore no longer collides. The "URL wins over code" priority still exists, under the `vg_maphash` name: a page URL carrying `?vg_maphash=<other hash>` loads that other hash.

This repo keeps the inline loading anyway: it works whatever the SDK version.

## Reporting the real load error

The SDK reports the real loading failure through `console.warn('VisioOne error:', error)` before rejecting with a generic "Cannot load the venue". The page captures that warning during `loadVenue` and sends the real cause to React Native in its `error` message, which the status badge shows.

## Message handshake

The page registers its message listeners before the SDK module has finished loading, then sends `page_ready`; React Native sends `setup` (map hash and load options) when it receives it. Listen to messages on both `window` and `document`: `react-native-webview` dispatches them on `window` on iOS and on `document` on Android.
